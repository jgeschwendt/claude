# Stele

- **Every jgeschwendt repo carries stele.** A repo without `.stele/` adopts it: a graph anchoring its docs page's claims (README or AGENTS where no page exists), the pre-push gate below, and stele in its root `check` task. A new repo adopts it in its first change. (since 2026-11-28 · "shouldn't stele be installed on all the project?")
- **Pre-push gate in any repo with `.stele/`: run `stele check && stele emit --check` before pushing.** Edits to files carrying `stele:landmark` anchors (or any node content) stale the committed `graph.lock`; rebuild with `stele build` locally and commit the lock alongside the change. CI runs `check`/`emit --check` only — never `build` — so a stale lock always fails remotely, one round-trip too late. Enforce mechanically, not by memory: give the repo an `hk.pkl` pre-push hook (`stele check && stele emit --check` + the test suite), pin hk in its `mise.toml` and install per clone with `hk install --mise` (hk replaced lefthook 2026-10-10, jdx tooling first); when adopting stele in a repo, add the hook in the same change. Any hook command that runs tests spawning git must open with `unset $(git rev-parse --local-env-vars)` — git exports `GIT_DIR` etc. into hook children, which points test fixtures' git at the host repo (it committed fixture junk onto stele's main, 2026-08-16). (since 2026-08-16 · routines run 31956326050; lefthook directive same day; hk since 2026-10-10)
- **Claim freshness is regional, not positional — verify with `stele check` at the exact commit, never by eyeballing lock diffs.** The lock stamps an AST digest of each claim's enclosing region (often the whole file), so an edit anywhere inside it stales the claim even far below the anchor line. When the working tree carries someone else's in-flight work, gate in a throwaway worktree: `git worktree add <tmp> <sha>`, run `check`/`emit --check` there, `stele build` the re-stamp if the claim still holds, commit it at that sha, then fast-forward the live branch with `git update-ref refs/heads/<branch> <new> <old>` — never `reset`, which would eat the in-flight tree. (since 2026-08-19 · visor 44383c3: a rail.js edit below every anchor still staled priv/cssom-only; caught only by gating at the commit)
- **"history unavailable (shallow clone?)" is more often an orphaned sha than a shallow clone — check `git cat-file -t <verified-sha>` before touching `fetch-depth`.** A history rewrite (squash to a new root, force-push) erases the commit every claim is stamped at, and no clone depth brings it back; stele 0.2.0's `fix:` line offers only `--unshallow` / `fetch-depth: 0`, a dead end in that case. Reproduce in a full local clone to rule depth out. Only churn-leashed claims (parser-less anchors — markdown, shell — which stamp no digest) fail, so a rewrite surfaces as a partial, unrelated-looking failure. Repair is the sanctioned manual path: re-read each failing anchor, satisfy yourself the claim still holds, `stele build`, commit the lock. The rebuild re-points every orphaned sha while leaving digests untouched — a diff of only `"sha"` lines is proof no content drifted. (since 2026-08-31 · grove CI run 33426221286 red at fetch-depth 0 on a one-commit history; grove d6a45a5 green)
- **The docs page is the design, the plan and the only prose source — `docs/index.html` on GitHub Pages, proxied at gigantic.dev/<project>/, with its figures drawn in the page.** No `docs/plan.md`, `docs/DESIGN.md`, `docs/PLAN.md` or any other design/plan markdown: delete on sight, folding unique content into the page; no "this page mirrors …" strip, because nothing mirrors anything. Figures are drawn in the page itself, live HTML/SVG or d3 charts on the gigantic design system's tokens, by the `artifacts` skill: no canvas, no PNG, no `docs/figures/`, no `figures` task; a page still carrying exported figures converts them when it is next touched, deleting `docs/figures/` in the same change. Claude Design is for previewing a UI or a look before it is built, never for a docs figure. (since 2026-11-10 · "drop it everywhere, update the rule"; Claude Design figures 2026-09-29 → 2026-11-10) The word is _figures_, never plates. Figure text is plain engineering language: the scriptural patterns the designs draw on (the creation week, the Sabbath, the ruach) stay as design sources and program names, but a figure labels the mechanism in plain terms (the week, the weekly review, the research engine), never the gloss. (since 2026-10-14 · "remove hebrew reckoning and ruach … from the figures … text not flow"; "we'll still ground in the ideas from the scriptures") Excalidraw, tldraw and `docs/*.tldr` are retired; strip a `tldraft check` gate when next touched. Specs that are contracts (SPEC.md, GUIDE.md, BANK-FORMAT.md) are not design docs and stay.
