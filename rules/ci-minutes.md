# Actions minutes

- **Private repos spend as few GitHub Actions minutes as possible.** Minutes on a private repo are metered, macOS at ten times the rate, and the account hit its limit on 2026-10-21 with bifrost's macOS job. A private repo's `ci.yaml` runs on `workflow_dispatch` only, never on push or pull_request; release artifacts build on this machine, and a release workflow runs on `workflow_dispatch` only, never on a tag push. The gates run on this machine, and a merge goes through the local background merge queue, the routine `~/.routines/merge-queue.md` (every 10 min on the `routine` tick, shown on bifrost's routines page): never open or merge a PR on a private repo expecting the cloud to gate it. Public repos keep their CI, and so do private repos in a paid org with its own minutes (imcs-solutions): their workflows keep push and pull_request triggers and their rulesets' required checks; the rule is for jgeschwendt's own private repos. (paid-org carve-out since 2026-11-02 · imcs#104: "revert for imcs this is a paid org, it has minutes to use")
- **To queue a PR, label it `queue`** — `gh pr edit <n> -R jgeschwendt/<repo> --add-label queue` — after review; the label is the admitting act, so a shift labels its own PR once its review step passes, and a PR nobody labelled never merges. The queue takes the oldest labelled PR per repo per tick, rebases it onto main in a throwaway worktree, runs the repo's gate (`mise run check` where the repo defines it, else `hk run pre-push`, else red "no gate"), and on green rebase-merges it against the sha it tested. Red: the gate's tail as a PR comment, the label removed, a docket problem thread keyed `merge-queue:<repo>:<n>`; re-label after the fix. A repo joining the queue gets a root `check` mise task first.
