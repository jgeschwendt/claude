# subether

The harness's Claude Code mod: it runs the session hooks that `settings.json` used to wire, shows what it injected in a pane, guards tool calls against the house rules, keeps the five-hour window clock, trails the markers a System One judge finds in the person's prompts, and puts the sandman shift above the prompt.

## Behaviour

- **Session hooks** — each binary runs from `$HOME/.local/bin` through `$.process.run`; a `--hook` call gets the settings hook's stdin JSON (the `classic.<Event>` event's `e`) on stdin, and its output is read as a command hook's: a JSON reply adds its `hookSpecificOutput.additionalContext` or nothing, other stdout adds itself. A missing binary, a timeout or a non-zero exit is a dim `$.ui.log` line and adds nothing; no exit code blocks.

  | event                                                                            | runs                                                                                                                                                                                                  | returns                                                                           |
  | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
  | `classic.SessionStart`                                                           | `sandman recall --hook`, `docket --hook`, `sandman report --hook`, 10 s each, and the dead-session sweep (`docket list --json`, then a `docket resolve` per stale thread, 5 s each), concurrently     | the chain's result plus each one's context, in that order, as `additionalContext` |
  | `classic.UserPromptSubmit`                                                       | `docket --hook`, 10 s                                                                                                                                                                                 | docket's pull as `additionalContext`                                              |
  | `classic.Stop`                                                                   | `docket --hook`, 10 s                                                                                                                                                                                 | the chain's result untouched                                                      |
  | `classic.Notification` (`agent_needs_input`, `idle_prompt`, `permission_prompt`) | `docket --hook`, 10 s                                                                                                                                                                                 | the chain's result untouched                                                      |
  | `classic.SessionEnd`                                                             | `sandman take --hook`, 1.5 s — the SessionEnd budget — and concurrently `docket list --json`, then `docket resolve <id> --reason "session ended"` per notification thread of the session, 0.75 s each | the chain's result untouched                                                      |

  The SessionEnd resolve closes the session's notification `problem` — its title the first line of its first message, trimmed and cut at 120 characters, as docket's Notification derives it, and no line of any message a Stop's `failed:` or `needs input:` directive (later notifications append to it) — by id: an `idle_prompt` fires after the turn's last `Stop`, so docket's own close on `Stop` never reaches it, and `docket --hook` ignores SessionEnd (verified 2026-10-19 · docket `src/verbs/hook.rs`, probe under `$DOCKET_ROOT`). A `--key` resolve would also close the `failed:` `problem` (body the whole message) and `needs input:` `decision` docket's Stop opens under the same `session:<id>` key, a second after it opened them — every `claude -p` run ends in SessionEnd — so those are left for the owner. A killed session fires no SessionEnd, so the SessionStart sweep closes what such sessions left: it reads the live session ids from `~/.claude/sessions/<pid>.json` (`sessionId`; the `<pid>.<hash>.key` files beside them are skipped), runs `docket list --json`, and `docket resolve <id> --reason "session gone"` for every notification-born `problem` thread (its title the first line of its first message, trimmed and cut at 120 characters, as docket's Notification derives it, and no line of any message a Stop's `failed:` or `needs input:` directive (later notifications append to it)) keyed `session:<id>` whose id is not live, adding no context. A headless `claude -p` session never registers, so a `problem` docket's Stop opened for one on a `failed:` message (its body the whole message, not the title) is never swept. An unreadable registry, or one not listing this session, skips the sweep: the format changed and absence is no evidence (verified 2026-10-19 · Claude Code 2.1.304, `~/.claude/sessions/<pid>.json` observed).

  A `classic.*` hook's result carries `additionalContext` on SessionStart, UserPromptSubmit and Stop, not on Notification or SessionEnd (verified 2026-10-14 · Claude Code 2.1.296 `ClassicResultFields`). Under managed settings an installed mod's `classic.*` hooks do not run (verified 2026-10-14 · `claude plugin validate`).

- **Guards** — a Bash `pkill -f`/`--full`; a tree discard — `git checkout` with `--`, `.`, `-f`/`--force`, `--ours`/`--theirs`, `--pathspec-from-file`, a `<rev> <path>` pair or a path that cannot be a branch (`./`, `:/`, `src/`, a glob), `git checkout-index -f`, `git switch -f`/`--force`/`--discard-changes`, `git restore` unless `--staged`/`-S` without `--worktree`/`-W`, `git read-tree -u`/`--reset`, and an inline `alias.…`/`include.…`/`includeIf.…` (`git -c`, `--config-env`, `GIT_CONFIG_KEY_<n>=`, `GIT_CONFIG_PARAMETERS=`, any case), which can hide any of them; `git reset --hard` (to `--ha`); `git push --force` (to `--forc`)/`-f` (bundled too)/`--force-with-lease` (to `--force-w`)/`+<refspec>`; `git stash` (not `list`/`show`); `git clean` (not `-n`/`--dry-run`) — and a `Write`/`Edit` to a `*.yml` path are denied with `subether: <house rule>.` as the reason, each denial trailed first: `sandman trail append --kind guard --rationale "<rule>: <first 200 chars of the command or path>" --ref session:<id>` (plus `--shift $SANDMAN_SHIFT` when set), 5 s; a trail that fails is one dim log line and the call is still denied. `-h`/`--help` after any git subcommand passes. The guard tokenizes the command as Bash would: quotes and escapes removed (`$'…'` decoded), each `$(…)` (its subshells and `case` patterns too), backtick, `<(…)`, `${…}`, `sh -c`/`bash -lc`/`eval` string, unquoted heredoc's groups and `find -exec`/`-ok` command checked as a command of its own, redirections and `#` comments, `((…))` arithmetic and `a=(…)` arrays dropped, quoted heredoc bodies skipped. Each command's argv is read past `VAR=value` words, keywords (`if`, `then`, `do`, `!`, `{`, `function f`, `coproc`, …) and wrappers with their options (`sudo -u me`, `env -i`, `nice -n 5`, `timeout -s KILL 5`, `xargs -I{}`, `mise x node@22 --`, `script -q <file>`, `time`, `watch`, `stdbuf`, `caffeinate`, `parallel`, `noglob`, `xcrun`, `mise -C <dir> x`, …), the command matched by basename, any case (the filesystem runs `GIT` as git); `command -v` only names. A command nested past 16 levels (`sh -c`, `eval`, `find -exec`, heredocs, `${…}`) or 64 groups deep, or one the guard fails to read, is denied as unreadable: the guard returns that reason, never throws. A guard that fails denies the call: a hook that throws or times out before passing the call on answers `subether: the guard could not read this call (<error, first line>) — it is denied, not run; rephrase the command`, trailed as a `guard` event with that text (a failing trail is one dim log line). Not seen: a saved alias, variable indirection (`G=git; $G …`), arguments fed from a pipe (`… | xargs git`), `env -S`, and package runners (`npx`, `bunx`). An `agent.spawn` with no `model` (forks aside) is pinned to `opus`.
- **Tool log** — every tool call (built-in and MCP, main loop and subagents, denied ones included: the hook is registered before the guards, so it runs outside them) appends one JSON line, after the call settles, to `<dir>/<yyyy-mm-dd>.jsonl`, the day local to the call's start; `<dir>` is `$CLAUDE_TOOL_LOG_DIR`, else `$XDG_STATE_HOME/subether/tools`, else `~/.local/state/subether/tools`. Keys in this order: `kind` (`call`; the shadow check writes `check` lines to the same file), `at` (ISO UTC, ms), `session`, `agent` (the subagent's id, `null` on the main loop), `cwd`, `tool`, `id` (the `tool_use_id`, or `null`), `ms` (from the hook's start to the settled result, a permission prompt included), `outcome` (`denied`, `error` or `ok`), `deny` (its text, on a denial only), `error` (`isError`), `readOnly` (`isReadOnly`), `chars` (the length of what the model read), `bash` (Bash records only: `{interrupted, background, stderr}`, `background` whether a `backgroundTaskId` is set, `stderr` its length), `input` (the tool's arguments, without `tool`, `tool_use_id`, `consent`, `agentId` and `requestMeta`, every string cut at 2,000 characters with `…[cut <n> chars]`). Never result content. The line goes through `sh -c 'mkdir -p … && cat >> <file>'` (O_APPEND, so sessions' lines interleave whole) and is not awaited, so the call returns without waiting on it; a failed append is one dim log line.
- **Shadow check** — auto mode's classifier spends Anthropic tokens on every call it decides; the owner: "i'd rather use my typesafe tokens for automode than my anthropic ones, lets shadow so we can shift spend to my typesafe subscription" (2026-11-06). A `tool.check` hook on every tool takes core's decision (`next(e)`) first and returns it unchanged; when it is `ask` on a real call (a `tool_use_id`, never a `$.tool.check` query) the tool does not report read-only — exactly the calls the classifier decides — the judge (`judge.ts`: TypeSafe first, Kev as fallback, the learned gate) is asked unawaited four `noul` questions — `destructive` (destroys, discards or rewrites work or history not the task's own), `outbound` (publishes, sends, pushes or uploads off the machine, or calls a paid API), `secrets` (reads, prints or moves credentials), `routine` (an ordinary, reversible step a careful engineer runs without asking) — over `{"cwd", "input": <the arguments, strings cut at 1,000>, "rules": <the house rules in one paragraph>, "tool"}`. Its answer is one line in the tool log's day file, keys in this order: `kind` (`check`), `at`, `session`, `agent`, `tool`, `id` (the `tool_use_id`, which joins it to the call's `call` line), `core` (`{decision, reason, rule, hook, setting}`, `null` when absent), `judge` (`typesafe` or `kev`), `markers` (the four probabilities, alphabetical), `tokens` (TypeSafe's billed input tokens, `null` from Kev), `ms` (the judge's latency). No judge answering is no line (the judge's own log lines say why); a failed append is one dim `subether check: …` line. It never changes a decision in this chunk: the classifier still decides every ask, and no threshold is applied.
- **Gauge** — under the prompt, in the hint line's place, the engine's hint kept beneath; the retired Rust statusline's line: `<model> (<effort>) <bar> <pct>% ≈<eta> · $<cost> · 5h <used>%† ↻ <reset>`, each segment only with its data, the bar taking what the row leaves of the window's columns less the statusline's 4-column margin (20 cells until the window is measured). The percent is against `autoCompactThreshold` (read from a `summary` breakdown, no request, whenever the window changes), else the window; the effort is the main loop's last `turn.step` effort; no `fast` flag, since no session-level fast mode reaches a mod; `†` past 200k context tokens. Fed by `session.measure` and, in interactive sessions, a 15 s `$.session.usage()` poll; yields to the engine's hint before the first reading.
- **Window clock** — each gauge reading carrying a `five_hour` window writes `window.json` (`$CLAUDE_WINDOW_FILE`, else `$XDG_STATE_HOME/claude/window.json`, else `~/.local/state/claude/window.json`), read by `sandman shift clock`, under the retired Rust statusline's `persist_window` rule (docs/index.html#gauge): only a window resetting within 6 h, never behind the file's live one, a percentage outside 0–100 logged and not written; a temp file `mv`'d into place, with no lock. A failure is one dim log line.
- **Context** — no native event injects at session start, so the session's first prompt stands in: the first `prompt.submit` that is not `isMeta` (and the first after `/clear`, which resets `$.state`) runs `sandman recall --hook` (10 s) on a SessionStart payload of the fields sandman reads (`cwd`, `hook_event_name`, `session_id`; the engine gives a mod no transcript path) and attaches its reply's `additionalContext` (or plain stdout) as one native `context` block after any the prompt carries. Capped at 10,000 characters: past it the head to the last line break, then `… [context cap: sandman recall printed <n> chars, cap 10000]`, and a log line. Tried once per session: a non-zero exit, nothing printed or a run that cannot start is one dim log line, attaches nothing, and is not retried; a failure shows in the pane. The prompt always goes through. Until cutover the installed perpetual's `classic.SessionStart` injects the same recall, so a session carries it twice (≈10 KB).
- **Pane** — `subether · injected` on the right: each attached block newest first, collapsed to its bold header `▸ <hh:mm> · <source> · <chars> chars[, cut]`, or for a failed recall `▸ <hh:mm> · sandman recall · failed`; with none, one dim line. The header is a button: a press (Tab to it and Enter while the pane has focus, or a click) expands the row to `▾ …` over its text, or error, dim, and a second collapses it. Opened unasked at an interactive session's start, which places it from 144 columns (else it waits undrawn); `/subether` opens it at any width, mid-turn too.
  - **Judge** — the pane's first line, dim: `judge · typesafe up · kev up`, a judge down for a time `typesafe down until <hh:mm> (rate limited)`, down for the session `typesafe down (key refused (401))`. Beneath the injected rows, a row per judged prompt (the newest 20), newest first: `▸ <hh:mm> · judged · <head, one line, cut at 40> · <likeliest marker> <p>` (`no judge` when none answered), expanding to the four probabilities, alphabetical, and `by <judge>, <n> input tokens`.
- **Shift row** (planned, in the band) — one dim line, cut to the band's width:
  `⟳ <shift> · <theme> · <repo> · <time to handoff> · last: <kind> <rationale>`.
  Read every 15 s from `~/.sandman/shifts/current.json` (`shift`, `theme`, `repo`, `handoff_by`) and the last line of
  today's (UTC) trail file `~/.sandman/trail/<yyyy>/<mm>/<dd>.jsonl`. Either may be missing; with neither, or while a survey shows, the band is left to
  the engine. Interactive sessions only.
- **Judged markers** — each prompt the person typed at the composer (`origin.kind` `composer`: never a `claude -p`, plugin, notification or meta prompt, nor a slash command or a dropped prompt) is judged once it entered, unawaited, so it never holds the prompt: one System One request asking four `noul` (yes-probability) questions — `correction` (it corrects what the assistant just did or said), `repeat` (it restates an instruction from the earlier prompts), `preference` (a durable rule for how work is done from now on), `approval` (go ahead) — over the state `{"previous answer": <the newest assistant text, its last 600 chars, left out when there is none>, "earlier prompts": <the last 3 judged prompts' first 200 chars>, "prompt": <the prompt>}`. TypeSafe first (`POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer $TYPESAFE_API_KEY`, model `jev-latest`, 3 s), Kev as fallback (`POST http://127.0.0.1:1703/v1/systemone`, model `kev-latest`, 5 s), nothing when both are down. Each marker at 0.8 or more runs `sandman trail append --kind correction --rationale "<prefix><first 200 chars> (p=<p, two decimals>, <typesafe|kev>)" --ref session:<id>` (plus `--shift $SANDMAN_SHIFT` when set), the prefix `repeated instruction: `, `preference: `, `approval: ` or none for a correction; several over the threshold are several events. Skipped, and kept out of the earlier prompts: a prompt over 400 characters, one starting `# ` (a shift or breath brief, a pasted document), and the opening prompt of a `claude --bg` session — dispatch's brief, which reaches the mod as a composer prompt of an interactive session; the one signal telling it apart is the daemon's `CLAUDE_CODE_SESSION_KIND=bg` (verified 2026-10-14 · Claude Code 2.1.299). The gate is learned, since neither judge documents a balance: an interactive session's start probes both with a free `GET /v1/models` (TypeSafe with the bearer), 1 s each, at once and unawaited; no key is TypeSafe down for the session; a 429/529 is down for its `Retry-After` (seconds or an HTTP-date; 60 s without one), a 401/403 for the session, a network error, a timeout, another status or a reply without the four answers 60 s (a Kev timeout `busy`); a judge whose time passed is tried again. Each failure is one dim log line `subether judge: <judge> down (<why>)`, both down beforehand one `subether judge: no judge up (…)`; nothing throws into the prompt. Cost: one request per typed prompt, whose input tokens TypeSafe bills (`usage.input_tokens`, kept per prompt for the pane); Kev is local.
- **`/shift`** runs `sandman shift status`, **`/docket`** `docket list`, **`/trail [n]`** `sandman trail log` cut to its last `n` lines (10 by
  default). Output is a `$.ui.log` line Claude never reads; all three run mid-turn.

## Installing it

The harness repo is a marketplace (`.claude-plugin/marketplace.json`); once per machine:

```sh
claude plugin marketplace add ~/.grove/code/jgeschwendt/claude/main
claude plugin install subether@jgeschwendt
```

The install enables it under `enabledPlugins` in the user `settings.json` — this repo's, through the `~/.claude` link — so every session loads it, `claude --bg` shifts included. The install is a versioned copy, not the trunk: `installed_plugins.json` pins `installPath` to `~/.claude/plugins/cache/jgeschwendt/subether/<version>`, taken at install, so a trunk edit is not live until it ships — each change bumps `version` in `.claude-plugin/plugin.json`, and goes live after `claude plugin update subether@jgeschwendt` on a pulled trunk (verified 2026-10-19 · the 0.2.0 copy from a97f0ee lacked later fixes).

## Checking it

```sh
claude plugin validate plugins/subether --strict
claude plugin test plugins/subether
```

The tests stub `$.process.run` and `$.http.fetch` beneath the mod, so no binary runs and no judge is asked; `HOME` is stubbed to `/home/test`.
