# Stele

- **Pre-push gate in any repo with `.stele/`: run `stele check && stele emit --check` before pushing.** Edits to files carrying `stele:landmark` anchors (or any node content) stale the committed `graph.lock`; rebuild with `stele build` locally and commit the lock alongside the change. CI runs `check`/`emit --check` only — never `build` — so a stale lock always fails remotely, one round-trip too late. Enforce mechanically, not by memory: give the repo a `lefthook.toml` pre-push gate (`stele check && stele emit --check` + the test suite) and pin lefthook in its `mise.toml`; when adopting stele in a repo, add the hook in the same change. Any hook command that runs tests spawning git must open with `unset $(git rev-parse --local-env-vars)` — git exports `GIT_DIR` etc. into hook children, which points test fixtures' git at the host repo (it committed fixture junk onto stele's main, 2026-08-16). (since 2026-08-16 · routines run 31956326050; lefthook directive same day)
- **Claim freshness is regional, not positional — verify with `stele check` at the exact commit, never by eyeballing lock diffs.** The lock stamps an AST digest of each claim's enclosing region (often the whole file), so an edit anywhere inside it stales the claim even far below the anchor line. When the working tree carries someone else's in-flight work, gate in a throwaway worktree: `git worktree add <tmp> <sha>`, run `check`/`emit --check` there, `stele build` the re-stamp if the claim still holds, commit it at that sha, then fast-forward the live branch with `git update-ref refs/heads/<branch> <new> <old>` — never `reset`, which would eat the in-flight tree. (since 2026-08-19 · visor 44383c3: a rail.js edit below every anchor still staled priv/cssom-only; caught only by gating at the commit)
- **"history unavailable (shallow clone?)" is more often an orphaned sha than a shallow clone — check `git cat-file -t <verified-sha>` before touching `fetch-depth`.** A history rewrite (squash to a new root, force-push) erases the commit every claim is stamped at, and no clone depth brings it back; stele 0.2.0's `fix:` line offers only `--unshallow` / `fetch-depth: 0`, a dead end in that case. Reproduce in a full local clone to rule depth out. Only churn-leashed claims (parser-less anchors — markdown, shell — which stamp no digest) fail, so a rewrite surfaces as a partial, unrelated-looking failure. Repair is the sanctioned manual path: re-read each failing anchor, satisfy yourself the claim still holds, `stele build`, commit the lock. The rebuild re-points every orphaned sha while leaving digests untouched — a diff of only `"sha"` lines is proof no content drifted. (since 2026-08-31 · grove CI run 33426221286 red at fetch-depth 0 on a one-commit history; grove d6a45a5 green)
- **The active plan is an in-repo docs node; its plate is made in Claude Design.** Once a repo has `.stele/`, a plan invisible to stele "violates the spirit" of `stele root` — a cold session finds map, invariants, hazards and what's next in one place — so `docs/plan.md` (visor's precedent) replaces any `~/.claude/plans` file on adoption. Plates (plan and page scenes) are drawn in Claude Design — the Artifact tool's Design type, `quickstart` with `intent: "design"` — and exported to `docs/plates/`; never in a `docs/*.tldr` drawing, and no repo gates them with `tldraft check` — tldraft is retired, strip its gate and drawings when a repo is next touched. Flow left-to-right, transit-map simple.
