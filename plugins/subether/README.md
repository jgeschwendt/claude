# subether

The harness's Claude Code mod: it seeds a session's first prompt with `sandman recall`, which also marks the session's start, and shows that and the agent's later pulls in a pane, guards tool calls against the house rules and logs every one and every typed prompt, keeps the gauge row and the five-hour window clock, pins a premium session's unpinned subagents to opus, hands each ending session to `sandman take`, and feeds every session's, agent's and turn's start and end to `census`. The `sandman report` context, the shift band and its commands are planned (chunks 7–8, below).

## Behaviour

Live:

- **Context** — no native event injects at session start, so the first prompt stands in: the first `prompt.submit` under each session id that carries an ask and is not `isMeta` — `origin.kind` `composer`, `bridge`, `slack-ping`, `sdk`, `scheduled-trigger` or `coordinator` (so again after `/clear`, and a `claude --bg` or `-p` session's opening brief); a task notification, a peer's or channel's message, an observer's, a plugin's, an auto-continuation or an unclassified prompt passes and leaves the slot for the next — runs `$HOME/.local/bin/sandman recall` (5 s; it bounds itself at 4) on `{"cwd", "interactive", "prompt", "session", "surface"}` — `prompt` the prompt's text, `interactive` whether `$.session.surfaces()` holds `terminal` (true under the REPL, as `session.start`'s `isInteractive`), `surface` its first (`session.start`'s `surface`), left out where nothing draws — the seed of the sandman repo's AGENTS.md `### sandman recall`. It writes the session's start mark (the one `sandman take` and the encode read; an episode with no `interactive` start mark is never encoded) and prints the instructions, the due work, the always-set and the prompt's ranked lines within 9,000 characters, attached as one native `context` block after any the prompt carries. Capped at 10,000 characters as a guard: past it the head to the last line break, then `… [context cap: sandman recall printed <n> chars, cap 10000]`, and a log line. Tried once per id: a non-zero exit or a run that cannot start or times out is one dim log line, attaches nothing, and is not retried; nothing printed (`CLAUDE_MEMORY_PIPELINE=1`) attaches nothing. Each lands in the pane. The prompt always goes through.
- **Gauge** — under the prompt, in the hint line's place, the engine's hint kept beneath; the retired Rust statusline's line: `<model> (<effort>) <bar> <pct>% ≈<eta> · $<cost> · 5h <used>%† ↻ <reset>`, each segment only with its data, the bar taking what the row leaves of the window's columns less the statusline's 4-column margin (20 cells until the window is measured). The percent is against `autoCompactThreshold` (read from a `summary` breakdown, no request, whenever the window changes), else the window; the effort is the main loop's last `turn.step` effort; no `fast` flag, since no session-level fast mode reaches a mod; `†` past 200k context tokens. Fed by `session.measure` and, in interactive sessions, a 15 s `$.session.usage()` poll; yields to the engine's hint before the first reading.
- **Guards** — a Bash `pkill -f`/`--full`; a tree discard — `git checkout` with `--`, `.`, `-f`/`--force`, `--ours`/`--theirs`, `--pathspec-from-file`, a `<rev> <path>` pair or a path that cannot be a branch (`./`, `:/`, `src/`, a glob), `git checkout-index -f`, `git switch -f`/`--force`/`--discard-changes`, `git restore` unless `--staged`/`-S` without `--worktree`/`-W`, `git read-tree -u`/`--reset`, and an inline `alias.…`/`include.…`/`includeIf.…` (`git -c`, `--config-env`, `GIT_CONFIG_KEY_<n>=`, `GIT_CONFIG_PARAMETERS=`, any case), which can hide any of them; `git reset --hard` (to `--ha`); `git push --force` (to `--forc`)/`-f` (bundled too)/`--force-with-lease` (to `--force-w`; `--force-with-lease=<ref>:<sha>`, a lease naming the commit it replaces, passes alone)/`+<refspec>`; `git stash` (not `list`/`show`); `git clean` (not `-n`/`--dry-run`) — and a `Write`/`Edit` to a `*.yml` path are denied with `subether: <house rule>.` as the reason, each denial marked first: `sandman mark` on `{"kind":"guard","rationale":"<rule>: <first 200 chars of the command or path>","session","tool"}`, 5 s, one `guard` line in sandman's ledger (the sandman repo's AGENTS.md `### sandman mark`; `sandman chart` lists them as `guards`); a mark that fails is one dim log line and the call is still denied. `-h`/`--help` after any git subcommand passes. The guard tokenizes the command as Bash would: quotes and escapes removed (`$'…'` decoded), each `$(…)` (its subshells and `case` patterns too), backtick, `<(…)`, `${…}`, `sh -c`/`bash -lc`/`eval` string, unquoted heredoc's groups and `find -exec`/`-ok` command checked as a command of its own, redirections and `#` comments, `((…))` arithmetic and `a=(…)` arrays dropped, quoted heredoc bodies skipped. Each command's argv is read past `VAR=value` words, keywords (`if`, `then`, `do`, `!`, `{`, `function f`, `coproc`, …) and wrappers with their options (`sudo -u me`, `env -i`, `nice -n 5`, `timeout -s KILL 5`, `xargs -I{}`, `mise x node@22 --`, `script -q <file>`, `time`, `watch`, `stdbuf`, `caffeinate`, `parallel`, `noglob`, `xcrun`, `mise -C <dir> x`, …), the command matched by basename, any case (the filesystem runs `GIT` as git); `command -v` only names. A command nested past 16 levels (`sh -c`, `eval`, `find -exec`, heredocs, `${…}`) or 64 groups deep, or one the guard fails to read, is denied as unreadable: the guard returns that reason, never throws. A guard that fails denies the call: a hook that throws or times out before passing the call on answers `subether: the guard could not read this call (<error, first line>) — it is denied, not run; rephrase the command`, marked as a `guard` line with that text (a failing mark is one dim log line). Not seen: a saved alias, variable indirection (`G=git; $G …`), arguments fed from a pipe (`… | xargs git`), `env -S`, and package runners (`npx`, `bunx`).
- **Pane** — `subether · recall` on the right (the sandman repo's docs/recall.html#pane): `recall · <n> pulls · <sent> sent`, then a row per recall — the seed, and each pull the agent ran, a Bash `sandman recall` or MCP `mcp__sandman__recall` whose result has a `recall · ` header — newest first, its bold header `<hh:mm>  seed|agent  <cue, 28>  <n> sent` (or `failed`). The newest is open, the rest shut; a header is a button (Tab to it and Enter while the pane has focus, or a click) that flips it. Open: the error of a failed seed; the path (the scorer, `hybrid, no decision model` or `lexical`, a failed stage named) and the seconds; a failed stage's cause; the seed's due work behind its own `due · <n>` button, open by default, a row `<id> <date>|waiting: <event> — <what>` each, an overdue date's in orange, then `… <n> more: <me> due`; the seed's always-set behind its own `always · <n>` button; each sent line `<score> <~><name>  <type>` under its bank, or `knowledge · <topic>` for a knowledge page or playbook, page or trace, a button that opens its description and `<me> show <path>`; `considered, not sent: <n>`; `nothing recalled…`. With no recall, one dim line. Opened unasked at an interactive session's start, which places it from 144 columns (else it waits undrawn); `/subether` opens it at any width, mid-turn too.
- **Census** — the feed `census state` and `census watch` fold (the census repo's `src/fold.rs`): one JSON event `{"event", "session", …}` into `$HOME/.local/bin/census emit` (500 ms), which stamps the time and appends it to the ledger; the emits queue one behind the other, so the ledger keeps the order the hooks fired in. Awaited: each `session.start` (cwd, model, surface, repository and working copy, entrypoint, session kind, engine version, platform, surfaces, transcript; a reader the host lacks leaves its field out) and `session.end`, each `agent.spawn` the engine started (under the `agentId` and model it answered, with the prompt's head; a denied spawn emits nothing), each `agent.report` (as `agent.end` with its status and the report's head) and each loop's `turn.start` and `turn.complete` (its length, usage and a refusal's category); a workflow script's agents raise no `agent.report`, so their own `turn.complete` also emits their `agent.end`. Never held for their event, and under the id read then: each non-meta `prompt.submit` (`prompt`: its head, origin, slash command, attachment count, the turn it was typed over, its wait), each `classic.SessionStart` (`session.open`: source, title, permission mode, model, a resume's idle seconds and tokens) and each `classic.Stop` (`tasks`: the background shells, monitors, workflows and scheduled wakeups still in flight, the turn's effort and permission mode, and the instruction files `classic.InstructionsLoaded` read since the last). Under the id the feed last read, dropped until it has one: each `tool.call` (`tool.start`, then `tool.end` with its outcome, what the model read counted, read-only, an error's or denial's head; named by the call's first target argument, cut at 200 characters), each `classic.PermissionRequest` (`tool.wait`, on that loop's call of the tool in flight) and `classic.PermissionDenied` (`tool.deny`), each model request (`step`, from a `turn.step` stream passed on chunk by chunk: model, effort, messages, whether it thought, the tools asked for and those the API ran, stop reason, usage), each `session.measure` reading that changed (`usage`, rate-limit windows included), each `session.compact` (`compact`, then `compact.end`), each slash command by name (`command`, never its arguments), skill (`skill`), `@` mention (`mention`), message sent (`message.send`, its head) and delivery received (`message.receive`, its size, never its text), remote client attaching or leaving (`client`), worktree made and given back (`worktree`, `worktree.end`), Stop pressed (`stop`), and the classic `ConfigChange` (`config`), `CwdChanged` (`cwd`), `DirectoryAdded` (`directory`), `Elicitation` and `ElicitationResult` (`elicit`), `Notification` (`notify`), `PostModelSwitch` (`model`), `StopFailure` (`turn.fail`), `TaskCreated` and `TaskCompleted` (`todo`) and `TeammateIdle` (`teammate.idle`); and a typing burst in the prompt box (`typing`, at most one per 5 s, never the text). Its senses: `hooks/senses.ts`, the manifest `bun senses/cli.ts --write` surveys from the engine-written types, records every event they offer (the classic hooks' too) with its top-level input fields, those census reads apart from the rest, and the version surveyed, beside `undeclared`, the fields a namespace's events carry at run time that the types do not declare (`classic.*`: `scratchpad_dir`), reviewed by hand and kept by every `--write`; bare, `senses/cli.ts` prints the drift a Claude Code update brings (`+`/`-` per event, field or read gained or lost; `!` per field census reads that the types no longer offer) and exits 1, and `bun test ./plugins/subether/senses` fails on the same lines. At run time a hook on `*`, outermost, compares each event's name and top-level keys with the manifest and emits `sense.new` (`name`, `key`, null for an unknown name, `engine`, `source` `mod`) once a session for each it lacks, a call on `$` and a tool's arguments aside; each opening but a compaction's also emits `senses` (`engine`, `reviewed`). It observes only: every hook answers what the engine answered, and a `census` that is missing, slow or failing is one dim log line.
- **Session end** — every `session.end`, whatever its `reason` (`prompt_input_exit`, `clear`, `resume`, `logout`, `other`), runs `sandman take` (1.5 s, awaited: the end's one short bound covers every hook and core) on `{"cwd", "reason", "session"}`, then passes the end on unchanged. The binary decides, not the mod (the sandman repo's AGENTS.md `### sandman take`): no start mark or `resume` writes nothing, a session a live `--bg` job names is held, and it records the end in sandman's ledger. A take that fails, times out or exits non-zero is one dim log line; the session still ends.
- **Subagent pin** — under the house rule that premium models plan and review and an unpinned spawn inherits the session model (`~/.claude/CLAUDE.md` "Operation"), an `agent.spawn` with no `model`, not a fork (`subagentType` `fork`, whose model is ignored: it always inherits), whose `parentModel` is premium (its id contains `fable` or `mythos`, any case) runs on `opus`, with one dim log line `pinned <description> to opus`. Any other spawn — a model given, a fork, a non-premium parent — passes as it came; a pin that fails passes the spawn on.
- **Tool log** — every tool call (built-in and MCP, main loop and subagents, denied ones included: the hook is registered before the guards, so it runs outside them) appends one JSON line, after the call settles, to `<dir>/<yyyy-mm-dd>.jsonl`, the day local to the call's start; `<dir>` is `$CLAUDE_TOOL_LOG_DIR`, else `$XDG_STATE_HOME/subether/tools`, else `~/.local/state/subether/tools`. Keys in this order: `kind` (`call`), `at` (ISO UTC, ms), `session`, `agent` (the subagent's id, `null` on the main loop), `cwd`, `tool`, `id` (the `tool_use_id`, or `null`), `ms` (from the hook's start to the settled result, a permission prompt included), `outcome` (`denied`, `error` or `ok`), `deny` (its text, on a denial only), `error` (`isError`), `readOnly` (`isReadOnly`), `chars` (the length of what the model read), `bash` (Bash records only: `{interrupted, background, stderr}`, `background` whether a `backgroundTaskId` is set, `stderr` its length), `input` (the tool's arguments, without `tool`, `tool_use_id`, `consent`, `agentId` and `requestMeta`, every string cut at 2,000 characters with `…[cut <n> chars]`). Never result content. The line goes through `sh -c 'mkdir -p … && cat >> <file>'` (O_APPEND, so sessions' lines interleave whole) and is not awaited, so the call returns without waiting on it; a failed append is one dim log line. Each prompt the person typed at the composer (`origin.kind` `composer`: never a `claude -p`, plugin, notification or meta prompt, nor a slash command or a dropped prompt) appends one unjudged `prompt` line to the same file once it entered, unawaited (a failed append is one dim `prompt log: …` line), keys in this order: `kind` (`prompt`), `at`, `session`, `head` (the prompt's first 120 characters, newlines as spaces). Skipped: a prompt over 400 characters, one starting `# ` (a shift or breath brief, a pasted document), and the opening prompt of a `claude --bg` session — its launcher's brief, which reaches the mod as a composer prompt of an interactive session; the one signal telling it apart is the daemon's `CLAUDE_CODE_SESSION_KIND=bg` (verified 2026-10-14 · Claude Code 2.1.299).
- **Window clock** — each gauge reading carrying a `five_hour` window writes `window.json` (`$CLAUDE_WINDOW_FILE`, else `$XDG_STATE_HOME/claude/window.json`, else `~/.local/state/claude/window.json`), read by `sandman shift clock`, under the retired Rust statusline's `persist_window` rule (docs/subether.html#gauge): only a window resetting within 6 h, never behind the file's live one, a percentage outside 0–100 logged and not written; a temp file `mv`'d into place, with no lock. A failure is one dim log line.

Planned, none wired until its chunk lands:

- **Session hooks** (planned · chunk 7) — perpetual's SessionStart work, carried over as the contract: the first `prompt.submit` that seeds (**Context**) also runs `$HOME/.local/bin/sandman report --hook`, 10 s, through `$.process.run`, concurrently with the seed, on a settings-hook SessionStart payload synthesized from the native event's fields. Its output is read as a command hook's — a JSON reply adds its `hookSpecificOutput.additionalContext` or nothing, other stdout adds itself — and attached as a native `context` block after the seed's. A missing binary, a timeout or a non-zero exit is a dim `$.ui.log` line and adds nothing; no exit code blocks.
- **Shift row** (planned · chunk 8, the `AbovePrompt` band) — one dim line, cut to the band's width:

  Read every 15 s from `~/.sandman/shifts/current.json` (`shift`, `theme`, `repo`, `handoff_by`) and the last line of
  today's (UTC) trail file `~/.sandman/trail/<yyyy>/<mm>/<dd>.jsonl`. Either may be missing; with neither, or while a survey shows, the band is left to

## Installing it

The harness repo is a marketplace (`.claude-plugin/marketplace.json`); once per machine:

```sh
claude plugin marketplace add ~/.grove/code/jgeschwendt/claude/main
claude plugin install subether@jgeschwendt
```

The install enables it under `enabledPlugins` in the user `settings.json` — this repo's, through the `~/.claude` link — so every session loads it, `claude --bg` shifts included. The marketplace is added from a local path and lists subether by a relative path (`./plugins/subether`), so the install loads in place from `main/plugins/subether`, not a cache copy: a change is live at the next session start or `/reload-plugins` once it is in the `main` worktree, with no `version` bump (Claude Code 2.1.318 docs, plugins-loading "In-place and copied plugins": "the plugin loads in place from its path inside the marketplace folder … you don't need to increase the version"). Verify at cutover: on 2026-10-19 perpetual's install was a versioned copy under `~/.claude/plugins/cache/jgeschwendt/perpetual/<version>`, so read the new entry's `installPath` in `~/.claude/plugins/installed_plugins.json`.

Until cutover the live `settings.json` loads `main/plugins/subether` through `env.CLAUDE_CODE_PLUGIN_DIRS` (a `~/` path, which that variable expands), in place as `--plugin-dir` does.

## Checking it

```sh
claude plugin validate plugins/subether --strict
claude plugin test plugins/subether
```

The tests stub `$.process.run` beneath the mod, so no binary runs; `HOME` is stubbed to `/home/test`.
